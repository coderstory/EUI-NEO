# 平台能力

页面代码通过 `eui/platform.h` 使用平台能力；底层实现位于 `core/platform/platform.h` / `core/platform/platform.cpp`。这里放跨平台、非业务的系统集成能力，例如打开 URL、文件选择对话框、托盘、IME 光标位置同步。

`core/` 中的 API 命名必须保持通用。文件选择只表达“选择文件”，不要在核心层写成媒体、图片、配置文件等业务概念；具体业务类型由调用方传入选项。

## 打开 URL

```cpp
eui::platform::openUrl("https://github.com/sudoevolve/EUI-NEO");
```

平台实现：

- Windows：`ShellExecuteA`
- macOS：`open`
- Linux：`xdg-open`

返回 `true` 表示系统接受了打开请求，不代表目标 URL 一定加载成功。

## 文件选择

推荐使用 `openFileDialog(...)`，它能区分选中、取消和失败：

```cpp
const eui::platform::FileDialogResult result =
    eui::platform::openFileDialog({
        "Select image",
        {".png", ".jpg", ".jpeg", ".webp"},
        "assets",
        "Images"
    });

if (result.selected()) {
    const std::string path = result.paths.front();
}
```

当前公开 API：

```cpp
struct FileDialogOptions {
    std::string prompt;
    std::vector<std::string> allowedExtensions;
    std::string initialDirectory;
    std::string filterName;
    bool allowMultiple = false;
};

enum class FileDialogStatus {
    Selected,
    Cancelled,
    Failed
};

struct FileDialogResult {
    FileDialogStatus status = FileDialogStatus::Cancelled;
    std::vector<std::string> paths;
    std::string error;

    bool selected() const;
};

eui::platform::FileDialogResult openFileDialog(const FileDialogOptions& options = {});
std::string chooseFile(const FileDialogOptions& options = {});
std::vector<std::string> chooseFiles(const FileDialogOptions& options = {});
```

### 选项说明

- `prompt`：对话框标题或提示文本。为空时使用默认提示。
- `allowedExtensions`：允许选择的扩展名列表。可以写 `"png"`、`".png"` 或 `"*.png"`；内部会统一转换。为空表示不过滤。
- `initialDirectory`：初始目录。为空时由系统决定默认位置。
- `filterName`：过滤器显示名称，例如 `"Images"`、`"Text files"`。为空时使用通用名称。
- `allowMultiple`：是否允许多选。`chooseFiles(...)` 会自动打开多选；`chooseFile(...)` 会强制单选。

### 类型过滤

类型过滤是扩展名过滤，不做文件内容探测。例如：

```cpp
eui::platform::FileDialogOptions options;
options.prompt = "Select data file";
options.allowedExtensions = {".json", ".csv", ".txt"};
options.filterName = "Data files";
```

平台转换方式：

- Windows：原生 `GetOpenFileNameW` 过滤器，例如 `*.json;*.csv;*.txt`。
- macOS：AppleScript `choose file of type {"json", "csv", "txt"}`。
- Linux：`zenity --file-filter`，不可用时回退到 `kdialog` 过滤器。

### 简单入口

不需要区分取消和失败时，可以使用兼容型入口：

```cpp
const std::string path = eui::platform::chooseFile({
    "Select file",
    {".txt", ".md"}
});

if (!path.empty()) {
    // user selected a file
}
```

多选：

```cpp
const std::vector<std::string> paths = eui::platform::chooseFiles({
    "Select files",
    {".png", ".jpg"}
});
```

`chooseFile(...)` 和 `chooseFiles(...)` 在用户取消或平台失败时都会返回空结果。需要展示错误信息时，使用 `openFileDialog(...)` 并检查 `result.status` / `result.error`。

### 结果处理

```cpp
const auto result = eui::platform::openFileDialog({
    "Select file",
    {".json"}
});

if (result.status == eui::platform::FileDialogStatus::Selected) {
    // result.paths
} else if (result.status == eui::platform::FileDialogStatus::Cancelled) {
    // user cancelled; usually no UI error needed
} else {
    // result.error contains a diagnostic message
}
```

## 平台依赖

- Windows：使用系统 Common Dialog，不需要额外运行时工具。
- macOS：使用系统 `osascript` 调用 `choose file`。
- Linux：优先使用 `zenity`，失败时尝试 `kdialog`。两者都不可用时，`openFileDialog(...)` 返回 `FileDialogStatus::Failed`。

## 当前限制

- 目前只支持打开本地文件。
- 暂不支持选择目录、保存文件、默认文件名、父窗口/modal 绑定。
- 文件选择是阻塞式系统对话框。适合在按钮点击回调里调用；不要在每帧 compose/update 中调用。

## 窗口效果（`core/platform/window_effect.h`）

标题栏外观（`applyTitleBarAppearance`）与 DWM backdrop（`applyWindowEffect`）的平台支持矩阵（磨砂设计文档 §3.6 降级链）：

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| 标题栏深浅联动（`TitleBarAppearance.dark`） | ✅ Win11 22000+（`DWMWA_USE_IMMERSIVE_DARK_MODE`） | ❌（Phase E：NSAppearance） | ❌ |
| 自定义标题栏底色（`customColor`） | ✅ Win11 22000+（`DWMWA_CAPTION_COLOR`，默认不用） | ❌ | ❌ |
| 透明帧缓冲半透（`WindowEffect::Transparent`） | ✅ GLFW 后端（需桌面合成；SDL2/Vulkan 降级 None） | ✅ GLFW 后端（`GLFW_TRANSPARENT_FRAMEBUFFER`；**注意 macOS 该属性由 `![NSWindow isOpaque]` 推导**，实现内不得改 `isOpaque`——GL 后端把该属性缓存在首个渲染帧选 blit 路径，改了会带偏会话级真值） | ❌ |
| Acrylic/Mica/MicaAlt backdrop | ✅ Win11 22H2（22621）+ GLFW 后端（`DWMWA_SYSTEMBACKDROP_TYPE`；能力缓存，失败静默降级） | ✅ `NSVisualEffectView`（`window_effect_macos.mm`；材质视图垫在 GL 视图之下，物性取值待实机复核） | ❌ |
| 非客户区（标题栏条）底色 | ✅ 系统代画（DWM backdrop 贯通非客户区） | ⚠️ AppKit 自画标题栏材质（非不透明窗同样会画，真机截图实测可见）；**主题色自绘标题栏未实现**，见下方已知限制 | ❌ |

不支持的平台/版本：`applyWindowEffect`/`applyTitleBarAppearance` 返回 `false`，调用方（`glfw_app_main`）按透明帧缓冲实际状态降级为 `Transparent`/`None` 并回写 `app::activeWindowEffect()`。运行时 API 与配置入口见 `docs/DSL.md`「窗口效果」一节。

### 已知限制（macOS）

- **主题色 / 材质贯通的标题栏未实现（曾实作后撤回，有真机证据）**：AppKit 只给不透明窗画标题栏背景，窗口带透明帧缓冲
  hint 时恒为非不透明 → 曾用 `NSWindowStyleMaskFullSizeContentView` + contentView 容器 + 标题栏条底（铺宿主 clearColor）
  补齐并让材质视图贯通标题栏。但真机截图实测：**FSCV 会把 GL surface 整体下移一个标题栏高（32pt）** —— 应用内容随之
  位移（亮段 114/219pt → 143/244pt）、底部被窗口底边裁掉、标题栏与内容之间留一条 66..95pt 全透明空带（透出桌面）。
  二分实测：去掉 FSCV 只留容器重挂载则一切正常（亮段与改前逐项一致）→ 偏移由 FSCV 引入，且无法从 EUI-NEO 侧可靠纠正
  （NSOpenGLContext 的 surface 定位在 AppKit 内部）。**取舍：几何零位移优先**，故不启用 FSCV，标题栏交给 AppKit 自画材质；
  若要主题色标题栏，需另想办法（候选：父窗下方的无边框子窗做条底，需先验证拖动/缩放同步无闪烁）。
- **macOS 上不得在运行期改窗口不透明性**：`GLFW_TRANSPARENT_FRAMEBUFFER` = `![NSWindow isOpaque]`
  （`3rd/glfw/src/cocoa_window.m` `_glfwFramebufferTransparentCocoa`），GL 后端把该属性缓存在首帧用于选择
  straight/premultiply blit 路径（`core/render/opengl/opengl_backend.cpp` `outputUsesTransparentFramebuffer`）→
  运行期 `setOpaque:` 会让会话内的 blit 路径与实际窗口状态不一致（切档后 alpha 合成出错）。窗口不透明性一律不动。
- **曾短暂存在的两个连带问题（已修）**：① 按档位 `setOpaque:YES` 带偏上述缓存；② 「None 档成功回写」让宿主半透档
  降级提示恒误报（`applyWindowEffectToWindow` 现按「透明帧缓冲是否生效」统一折法，macOS 分支）。
- Windows 侧「`WindowEffect::None` 成功回写 vs 半透档降级判据」的同一不一致已知（详见
  `core/app/glfw_app_main.cpp` `applyWindowEffectToWindow` 内 `#else` 注释），待有 Windows 实机时另行处理。
